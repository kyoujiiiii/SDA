## 1. Контекст и проблематика
Современные компании стремятся активно использовать внешние облачные сервисы, SaaS-платформы и большие языковые модели (LLM: OpenAI, Anthropic Claude, облачные хранилища). Однако регуляторные требования (GDPR, Swiss FADP / nDSG), коммерческая тайна и стандарты безопасности запрещают передавать во внешнюю среду чувствительные и конфиденциальные данные:
* Персональные данные (PII: ФИО, email, телефоны, швейцарские номера социального страхования AHV/AVS).
* Финансовые сведения (IBAN, номера счетов, суммы контрактов).
* Секреты инфраструктуры (API-ключи, токены, внутренние IP-адреса).

### Цель проекта
Разработать защитный прокси-слой (**Swiss Data Airlock**), который:
1. Перехватывает исходящий поток данных (текст, промпты, документы).
2. Автоматически находит конфиденциальные сущности и заменяет их плейсхолдерами/токенами перед выходом в публичную сеть.
3. Сохраняет соответствие (маппинг) в изолированном локальном защищенном хранилище.
4. На обратном пути прозрачно восстанавливает оригинальные данные (демаскирует), но исключительно для **авторизованных пользователей** с соответствующим уровнем доступа.

## 2. Ключевые требования к MVP

### 2.1. Модуль обнаружения чувствительных данных (Sensitive Data Detector)
* Обнаружение типовых сущностей: Имена, Email, Телефоны, Локации, Суммы, Ключи авторизации.
* Поддержка швейцарской специфики: швейцарские IBAN (начинаются с `CH`), номера AHV/AVS (`756.xxxx.xxxx.xx`), адреса/кантоны.
* Реализация: гибрид RegEx-правил и легковесных локальных NER-моделей (например, Microsoft Presidio, spaCy).

### 2.2. Двусторонний шлюз токенизации (Tokenization / Detokenization Engine)
* **Outbound (Маскирование):**  
  *Исходный запрос:* `«Проанализируй контракт с Hans Peter на сумму 500,000 CHF, IBAN CH9300000000000»`  
  *Payload в облако/LLM:* `«Проанализируй контракт с [PERSON_1] на сумму [AMOUNT_1], IBAN [IBAN_1]»`
* **Vault / State Management:**  
  Безопасный локальный реестр маппинга токенов к оригинальным значениям в рамках сессии/запроса (в памяти, SQLite или Redis). Внешний сервис никогда не видит реальные значения.
* **Inbound (Восстановление):**  
  *Ответ от LLM:* `«Условия контракта для [PERSON_1] на [AMOUNT_1] выгодны...»`  
  *Ответ авторизованному клиенту:* `«Условия контракта для Hans Peter на 500,000 CHF выгодны...»`

### 2.3. Ролевой доступ и безопасность (RBAC)
* **Авторизованный пользователь (Admin / Data Owner):** получает демаскированный, читаемый текст.
* **Неавторизованный пользователь / Облачный провайдер / Аудитор:** видит исключительно токенизированный текст с плейсхолдерами.

## 3. Архитектурный стек для хакатона

| Компонент | Назначение | Рекомендуемые технологии |
| :--- | :--- | :--- |
| **Airlock Proxy / Gateway** | Перехват запросов, маршрутизация трафика | Python (FastAPI / Starlette) или Node.js |
| **Detection & Anonymization** | Анализ сущностей и замена токенами | Microsoft Presidio / spaCy / Regex Engine |
| **Secure Token Vault** | Хранение таблицы сопоставления токенов | In-Memory Key-Value / Redis / SQLite |
| **External LLM Integration** | Интеграция с внешним облаком | OpenAI API / Anthropic API / LangChain |
| **Interactive Demo UI** | Наглядная презентация работы шлюза | Streamlit / Gradio / Next.js + Tailwind CSS |

## 4. Сценарий демонстрации для жюри (Demo Flow)

1. **Интерактивный экран (Split-Screen / 3-Column View):**
   * **Колонка 1 (Вход):** Сырой конфиденциальный запрос пользователя.
   * **Колонка 2 (Airlock Outbound):** Что видит внешнее облако (чистый текст с плейсхолдерами `[PERSON_1]`, `[IBAN_1]`).
   * **Колонка 3 (Результат):** Финальный ответ с восстановленными сущностями.
2. **Демонстрация ролевой модели (Role Switcher):**
   * Переключение прав в один клик: режим *«Сотрудник»* (полный доступ) $\leftrightarrow$ режим *«Внешний лог / Cloud View»* (данные остаются замаскированными).
3. **Скорость работы:**
   * Минимальный оверхед (задержка на маскирование/демаскирование < 150 мс).

## 5. План реализации на хакатоне (24–48 часов)

* **Этап 1 (0–6 ч):** Каркас FastAPI-прокси, подключение Microsoft Presidio / регулярных выражений, базовый vault для маппинга.
* **Этап 2 (6–18 ч):** Реализация цикла «Запрос $
ightarrow$ Маскирование $
ightarrow$ OpenAI API $
ightarrow$ Демаскирование $
ightarrow$ Ответ».
* **Этап 3 (18–30 ч):** Разработка UI-дашборда (Streamlit / Next.js) с наглядным отображением потока данных.
* **Этап 4 (30+ ч):** Тестирование граничных случаев, швейцарские паттерны (AHV, IBAN), подготовка питча и слайдов с акцентом на ценность для Natron.io.
